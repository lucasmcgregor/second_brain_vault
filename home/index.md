# home — Vault Root

The owner's half of the vault: where their thinking lives and where collaboration happens. The organising question is **does this work end?**

| Folder | Shape of the work | Example |
|---|---|---|
| [[home/projects/index]] | Has a goal and a finish line | Plan a trip, ship a report, move house |
| [[home/activities/index]] | Ongoing, no end date | Reading, a running practice, managing finances |
| [[home/documents/index]] | Reference they are cataloguing | Notes on a book, a how-to, a contact list |
| [[home/personal/index]] | Private and personal | Health, family, anything they flag private |
| [[home/archives/index]] | Finished or dormant, kept | A completed project, a dropped activity |

## Where to file something new

1. Does it have a defined end state? → **project**
2. Will they keep doing it indefinitely? → **activity**
3. Is it information rather than work? → **document**
4. Is it personal or private? → **personal** (this wins over the others)
5. Is it done or dormant? → **archive** — but ask first

If a project and an activity both fit, prefer the project and link it from the activity. Projects finish; activities accumulate them.

## Working here

- **This half stays clean.** Drafts, scratch and task state go in `_ai/memory/transient/`, never here.
- Ask before creating a new top-level folder. The five above should cover almost everything.
- Ask before moving anything to archives. Archiving is reversible, but it is the owner's call.
- Link across areas with `[[wikilinks]]` — the owner navigates this graph in Obsidian by hand, not only through you.
- Never pull `personal/` content into work context unasked.

## Scan order

Follow the routing table in the root `AGENTS.md`. Read the one relevant area index and stop there. Do not sweep all five folders to answer a question about one of them, and do not touch `archives/` unless directed.
